Görev Eklentisi — Web sürümü (Mac, Outlook web, yeni Outlook, tarayıcı)

Windows'taki klasik Outlook için kurulum paketi (VSTO eklentisi) kullanılır. Diğer platformlar için aynı görev sistemi bir Office web eklentisi ve tarayıcı uygulaması olarak çalışır. İki sürüm aynı görev maillerini okuyup yazar; kullanıcılar hangi sürümü kullanırsa kullansın birbirine görev verebilir.

PlatformKullanılan sürüm
Windows — klasik Outlook 2016 / 2019 / 2021 / Microsoft 365Kurulum paketi (GorevEklentisi-Kurulum.exe)
Windows — yeni OutlookWeb eklentisi
macOS — OutlookWeb eklentisi
Outlook web (outlook.office.com, outlook.com) — her işletim sistemiWeb eklentisi
Linux ve diğerleri (Outlook kurulu olmadan)Tarayıcı uygulaması

Koşul: posta kutusu Microsoft 365 (Exchange Online) ya da Outlook.com olmalıdır. IMAP / POP / Gmail hesapları web sürümünde desteklenmez (Outlook bu hesaplarda web eklentisi yüklemez; tarayıcı uygulaması da posta kutusuna Microsoft Graph ile erişir). Bu hesaplar yalnızca Windows'taki kurulum paketiyle kullanılabilir.

Adresler (yayın adresi web-eklenti/yayin.json → taban):

  • İndirme sayfası: https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/
  • Tarayıcı uygulaması: https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/eklenti/
  • Eklenti dosyası (manifest): https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/eklenti/manifest.xml

1. Bir kerelik kurulum (yayıncı)

1.1 GitHub Pages

Dağıtım deposunda Settings → Pages → Build and deployment → Source: Deploy from a branch, dal main, klasör / (root) seçilip kaydedilir. Birkaç dakika sonra yukarıdaki adresler açılır. Sonraki derlemeler siteyi kendiliğinden günceller.

1.2 Uygulama kaydı (Microsoft Entra)

Eklenti posta kutusuna kullanıcının kendi oturumuyla (Microsoft Graph) erişir; bunun için bir uygulama kaydı gerekir. Kayıt ücretsizdir, sunucu ya da gizli anahtar içermez.

  1. https://entra.microsoft.com → Applications → App registrations → New registration.
  2. Name: Görev Eklentisi. Supported account types: Accounts in any organizational directory and personal Microsoft accounts.
  3. Redirect URI: platform Single-page application (SPA), adres https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/eklenti/index.html → Register.
  4. Authentication → Single-page application → Add URI: brk-multihub://caglarutkuguler.github.io (Outlook içindeki oturum için) → Save.
  5. API permissions → Add a permission → Microsoft Graph → Delegated permissions: User.Read, Mail.ReadWrite, Mail.Send, People.Read → Add permissions.
  6. Overview sayfasındaki Application (client) ID değeri web-eklenti/yayin.json dosyasındaki istemciKimligi alanına yazılır ve derleme yeniden çalıştırılır. Bu değer gizli değildir.

Kimlik tanımlanana kadar uygulama "Kurulum tamamlanmadı" iletisini gösterir.

Kullanıcı onayına izin vermeyen kurumlarda bir yöneticinin izinleri kurum adına onaylaması gerekir (Entra → Enterprise applications → Görev Eklentisi → Permissions → Grant admin consent).

2. Eklentiyi Outlook'a ekleme

Kullanıcı kendisi ekler (Outlook web, yeni Outlook, Mac):

  1. Eklenti dosyası (manifest.xml) indirme sayfasından indirilir: https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/
  2. Outlook'un "Eklentiler" penceresi açılır. Tarayıcıda, eklentinin ekleneceği hesapla oturum açıkken:
    • iş / okul hesabı: https://outlook.office.com/mail/inclientstore
    • kişisel hesap (Outlook.com, Hotmail): https://outlook.live.com/mail/0/inclientstore
    • bağlantı pencereyi açmazsa: Outlook'ta bir ileti açılır, iletinin üstündeki Uygulamalar düğmesinden Eklenti al seçilir.

Pencere yalnızca Outlook posta kutusu olan hesaplarda açılır. Posta kutusu (Exchange Online lisansı) olmayan bir Microsoft hesabıyla oturum açıksa bağlantılar boş sayfa ya da hata gösterir.

  1. Eklentilerim → Özel eklentiler → Özel eklenti ekle → Dosyadan ekle ile indirilen manifest.xml seçilir, Yükle denir.

Kurum genelinde (Microsoft 365 yöneticisi): Microsoft 365 yönetim merkezi → Ayarlar → Tümleşik uygulamalar → Özel uygulamaları karşıya yükle → Office Eklentisi → bildirim dosyası bağlantısı olarak manifest.xml adresi verilir, kullanıcılar/gruplar seçilir. Eklenti seçilen herkesin Outlook'unda (web, Mac, yeni ve klasik) kendiliğinden görünür.

Eklenti bir ileti açıkken Görev grubundaki (ya da iletideki Uygulamalar menüsündeki) Görevler ve Yeni Görev düğmeleriyle açılır. İlk kullanımda Microsoft'un izin onayı penceresi bir kez çıkar.

Outlook olmadan (Linux vb.): tarayıcı uygulamasının adresi açılır, Microsoft hesabıyla oturum aç denir.

3. Nasıl çalışır

  • Sunucu bileşeni yoktur. Görevler posta kutusundaki görev maillerinden okunur (Gelen Kutusu, Görevler klasörü, Gönderilmiş Öğeler) ve tarayıcıda yerel olarak saklanır; işlemler görev maili olarak gönderilir.
  • Pencere açıkken iki dakikada bir ve ⟳ düğmesiyle eşitlenir. Web eklentileri arka planda çalışamadığından yeni görev bildirimi çıkmaz; görev maili Gelen Kutusu'na normal e-posta olarak düşer.
  • Bağlantı yokken yapılan işlemler bekletilir, bağlantı gelince gönderilir.
  • Aynı posta kutusu hem Windows eklentisiyle hem web sürümüyle kullanılabilir: biri diğerinin yaptığı işlemleri Gönderilmiş Öğeler'den okur.
  • Görev maillerindeki Kabul Et / İş Kaydı… düğmeleri yalnızca Windows eklentisinde çalışır; web sürümünde bölmedeki düğmeler kullanılır.

5. Geliştirme

  • Kaynak: web-eklenti/kaynak/ (çekirdek, depo, servis, Graph, formlar, köprü). Liste / kanban / Gantt / yük arayüzü Windows eklentisiyle ortaktır: src/GorevEklentisi.Addin/web/.
  • cekirdek.js, GorevEklentisi.Core'un (C#) karşılığıdır; olay modeli, kurallar ya da mail biçimi değişince iki taraf birlikte güncellenir.
  • Derleme: node web-eklenti/derle.mjs --taban <https adresi> --surum a.b.c --istemci <uygulama kimliği> → web-eklenti/dist/.
  • Testler: node --test web-eklenti/test/akis.test.mjs (çekirdek + servis, sahte posta); node web-eklenti/test/arayuz.mjs (Playwright ile arayüz akışı).

NCU Task Tracker — Web edition (Mac, Outlook on the web, new Outlook, browser)

For classic Outlook on Windows, the installation package (VSTO add-in) is used. For other platforms the same task system works as an Office web add-in and a browser app. Both editions read and write the same task mails; users can assign tasks to each other regardless of which edition they use.

PlatformEdition used
Windows — classic Outlook 2016 / 2019 / 2021 / Microsoft 365Installation package (GorevEklentisi-Kurulum.exe)
Windows — new OutlookWeb add-in
macOS — OutlookWeb add-in
Outlook on the web (outlook.office.com, outlook.com) — every operating systemWeb add-in
Linux and others (without Outlook installed)Browser app

Requirement: the mailbox must be Microsoft 365 (Exchange Online) or Outlook.com. IMAP / POP / Gmail accounts are not supported in the web edition (Outlook does not load web add-ins for these accounts; the browser app also accesses the mailbox through Microsoft Graph). These accounts can be used only with the installation package on Windows.

Addresses (publication address: web-eklenti/yayin.json → taban):

  • Download page: https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/
  • Browser app: https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/eklenti/
  • Add-in file (manifest): https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/eklenti/manifest.xml

1. One-time setup (publisher)

1.1 GitHub Pages

In the distribution repository, Settings → Pages → Build and deployment → Source: Deploy from a branch is selected, branch main, folder / (root), and saved. After a few minutes the addresses above open. Later builds update the site automatically.

1.2 App registration (Microsoft Entra)

The add-in accesses the mailbox with the user's own sign-in (Microsoft Graph); this requires an app registration. Registration is free and contains no server or secret key.

  1. https://entra.microsoft.com → Applications → App registrations → New registration.
  2. Name: NCU Task Tracker. Supported account types: Accounts in any organizational directory and personal Microsoft accounts.
  3. Redirect URI: platform Single-page application (SPA), address https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/eklenti/index.html → Register.
  4. Authentication → Single-page application → Add URI: brk-multihub://caglarutkuguler.github.io (for the sign-in inside Outlook) → Save.
  5. API permissions → Add a permission → Microsoft Graph → Delegated permissions: User.Read, Mail.ReadWrite, Mail.Send, People.Read → Add permissions.
  6. The Application (client) ID value on the Overview page is written to the istemciKimligi field in the web-eklenti/yayin.json file and the build is run again. This value is not secret.

Until the ID is defined, the app shows the "Setup is not complete" message.

In organizations that do not allow user consent, an administrator must approve the permissions on behalf of the organization (Entra → Enterprise applications → NCU Task Tracker → Permissions → Grant admin consent).

2. Adding the add-in to Outlook

The user adds it themselves (Outlook on the web, new Outlook, Mac):

  1. The add-in file (manifest.xml) is downloaded from the download page: https://caglarutkuguler.github.io/gorev-eklentisi-dagitim/
  2. Outlook's "Add-ins" window is opened. In the browser, while signed in with the account the add-in is to be added to:
    • work / school account: https://outlook.office.com/mail/inclientstore
    • personal account (Outlook.com, Hotmail): https://outlook.live.com/mail/0/inclientstore
    • if the link does not open the window: a message is opened in Outlook, and Get Add-ins is selected from the Apps button at the top of the message.

The window opens only for accounts that have an Outlook mailbox. If signed in with a Microsoft account that has no mailbox (Exchange Online license), the links show a blank page or an error.

  1. With My add-ins → Custom Addins → Add a custom add-in → Add from file, the downloaded manifest.xml is selected and Upload is clicked.

Organization-wide (Microsoft 365 administrator): Microsoft 365 admin center → Settings → Integrated apps → Upload custom apps → Office Add-in → the manifest.xml address is given as the manifest file link, and users/groups are selected. The add-in appears automatically in the Outlook of everyone selected (web, Mac, new and classic).

The add-in is opened with the Tasks and New Task buttons in the Task group (or in the Apps menu on the message) while a message is open. On first use, Microsoft's permission consent window appears once.

Without Outlook (Linux etc.): the address of the browser app is opened and Sign in with Microsoft is clicked.

3. How it works

  • There is no server component. Tasks are read from the task mails in the mailbox (Inbox, Task Mail folder, Sent Items) and stored locally in the browser; actions are sent as task mails.
  • While the window is open, it syncs every two minutes and with the ⟳ button. Since web add-ins cannot run in the background, no new task notification appears; the task mail arrives in the Inbox as a normal e-mail.
  • Actions performed while there is no connection are held and sent when the connection returns.
  • The same mailbox can be used with both the Windows add-in and the web edition: each reads the actions made by the other from Sent Items.
  • The Accept / Work Log… buttons in task mails work only in the Windows add-in; in the web edition the buttons in the pane are used.

5. Development

  • Source: web-eklenti/kaynak/ (core, store, service, Graph, forms, bridge). The list / Kanban / Gantt / workload interface is shared with the Windows add-in: src/GorevEklentisi.Addin/web/.
  • cekirdek.js is the counterpart of GorevEklentisi.Core (C#); when the event model, the rules or the mail format change, both sides are updated together.
  • Build: node web-eklenti/derle.mjs --taban <https adresi> --surum a.b.c --istemci <uygulama kimliği> → web-eklenti/dist/.
  • Tests: node --test web-eklenti/test/akis.test.mjs (core + service, fake mail); node web-eklenti/test/arayuz.mjs (UI flow with Playwright).
